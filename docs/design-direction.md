# 原创 UI/UX 方向：侧席

日期：2026-09-24。用户要求：数据库方案可参考 ARAM-tool，UI/UX 独立设计。“侧席”是设计方向名称，产品正式使用 Game Wingman。

## 目标与设计取舍

面向对局中需要快速查阅攻略的桌面玩家。浮窗的首要任务是在短暂一瞥中说明当前参考、依据和不确定信息；详细设置留在主窗口。

桌面应用采用主控制窗口与独立窄幅浮窗。按用户要求将 UI 收紧：默认只露出一条信息，不展示排行榜、聊天记录、模拟棋盘或多列攻略。设置与资料搜索放在次级面板。

主窗口的第一层只有三个按钮：**选择窗口、开始 / 暂停读取、显示 / 隐藏浮窗**。中间用于确认实际读取的画面，下方保留“导入截图”。权限说明、完整试用说明与数据版本按需查看。

```text
折叠                      阅读                         展开依据
┌────────────┐           ┌──────────────────────┐     ┌──────────────────────┐
│ GWM · 更新 │           │ GWM / TFT    暂停 收起 │     │ 攻略来源              │
└────────────┘           │ 可见信息 · 校正         │     │ 适用版本 / 更新时间    │
                         │ 一条主提示              │     │ 来源条目 / 推断范围    │
                         │ 一行补充说明             │     │ 返回当前提示           │
                         │ 依据与版本         展开  │     └──────────────────────┘
                         └──────────────────────┘
```

独有的视觉元素是一条左侧“折页边签”：将读取状态、当前提示与依据串在固定阅读顺序中。边签颜色仅表示有效、待确认、过期三类状态，旁边始终有文字。其余界面保持克制，避免重复嵌套卡片、排行榜或长篇聊天记录。

## 视觉 tokens

| 用途 | 值 |
| --- | --- |
| 工作区底色 / 雾蓝 | `#E6ECEE` |
| 浮窗底色 / 深海蓝 | `#21333E` |
| 浮窗文字 / 纸白 | `#F2F5F4` |
| 主色 / 海松 | `#A8D0C6` |
| 待确认 / 沙金 | `#E8C487` |
| 次级文字 / 石蓝 | `#A9BBC4` |

应用统一使用系统字体（PingFang SC / Microsoft YaHei / system-ui）。主窗口标题 16 px，浮窗主信息 21 px；主按钮高 38 px，浮窗按钮 32 px。不用展示型大标题、网页导航或营销文案。主窗口默认 880 × 650，浮窗 320 × 248，收起后高 52。

## 交互规范

- 浮窗可拖动、收起、暂停、隐藏；完整窗口只承载权限、数据来源和设置。
- 不确定字段提供原地校正。未确认的信息不驱动确定性建议。
- 来源与版本展开查看，不挤占主要提示的位置。
- 点击穿透与编辑模式通过桌面全局快捷键切换；浏览器草案只演示模式变化，不冒充原生穿透。
- 更新保留阅读锚点，不闪屏、不自动弹出大面板、不抢焦点。
- 权限拒绝、无匹配和过期状态给出具体下一步，保留已有内容的时间和版本。
- 界面不以百分比置信度制造精确感；未经校准时用“已识别 / 待确认”。

## 当前实现

`src/renderer/index.html` 是 Electron 主窗口，`src/renderer/overlay.html` 是独立原生置顶窗口。应用从本地文件加载 UI，不依赖浏览器、网页标签或本地 HTTP 服务。

窗口选择、图片导入、读取 / 暂停、浮窗显示 / 隐藏 / 收起、透明度和系统点击穿透已接入桌面接口。画面处于什么状态就显示什么状态；未接入识别时显示“识别与攻略尚未接入”。资料支持手动搜索并固定到浮窗，明确标注“手动固定 · 名称资料”，不冒充 AI 建议。
