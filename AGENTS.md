# Game Wingman development context

Read `README.zh-CN.md`, `docs/windows-handoff.md` and `docs/api-providers.md` before continuing this project.

- Build a desktop app for Windows/macOS. Do not replace it with a website. The next gameplay validation target is Windows.
- Keep UI simple: three primary controls, a single-item floating overlay, secondary data/settings panels.
- Capture only explicitly selected windows, imported images, or the unique game window found by user-authorized auto discovery. Auto discovery checks titles and Windows game-process window handles; ambiguous candidates require selection. No game-memory reading, process injection or input automation. Ordinary tests must disable discovery or replace the entire source inventory with fixtures.
- Current adapters support MiniMax (CN/global), DeepSeek and Gemini. Desktop calls are locked to DeepSeek Flash with a persistent CNY 10 budget. Manual images require per-image consent; live video sampling requires explicit session consent. OP.GG's full current main-page set (50 comp variants), 137 items and 55 recipes are available. Local craft planning follows the selected comp's core priorities, deducts owned items and allocates each component once; it does not assess opponents, augments or current board strength. Read docs/deepseek-first-test.md and docs/guide-preview.md.
- Store and use credentials in the main/Node layer. New user-entered keys may travel one way from the masked main-window input to encryption; never return saved keys/ciphertext through renderer IPC, commit filled templates/`.env`, bundle keys or silently send screenshots. Key save/import never enables AI or switches the active provider; generated templates stay empty.
- Do not make live paid provider calls as part of tests. Use injected mock fetch. Live probes must be explicitly requested and configured.
- No automatic provider fallback: switching providers changes data recipients and cost.
- Data sources are not restricted to OP.GG. Follow docs/data-sources.md: maintain GitHub-visible source/author links, usage and transformations, version/timestamp/statistical scope, rights references and integration status. Update dataset provenance and THIRD_PARTY_NOTICES.md with every applicable source change; do not label candidates as active or combine incompatible samples.
- Tactical explanations need reviewed, versioned sources. Never pass off a name dictionary, unverified model output or an old frame as a current guide.
- Daily TFT data updates follow official published patch notes, cache facts across restart, and compare OP.GG rankings independently by top-four/first-place. Recipes remain separately versioned and require review after official changes. Do not turn the data updater into a binary software updater; the user explicitly chose TFT patch/data updates only. Read docs/daily-data-updates.md.
- TFT equipment tracking now directly updates crafts for the selected/current recommended comp. Reference gear remains visible when inventory is unknown; 39/50 source boards have coordinates. Per-comp augment candidates load on expansion through bounded public requests and a six-hour cache, without AI. They do not rank the player's actual three choices or optimize current positioning. Read docs/automatic-equipment.md. Keep other-game research separate from this TFT delivery.
- TFT entity icons come from validated OP.GG metadata and load through a bounded main-process raster cache; never relax renderer CSP or use arbitrary remote URLs. Keep visible quantities, accessible names and offline text fallback. The latest local package variant is auto-follow-preview. Hidden tests must pass an isolated --user-data-dir and use mocked image transport (optional previously fetched public image fixtures), never the user's profile or paid API.
- Keep experimental-use and account-ban notices visible in documentation. Do not claim Riot approval or game compatibility from synthetic tests.
- Preserve unrelated work. State local checks, CI checks, packaging, real game validation and publication separately.
- This is currently a public source preview with `UNLICENSED` status; do not invent a reuse license or copy third-party guide corpora.

Commands: `npm ci`, `npm run check`, `npm test`; for desktop changes, `npm run test:desktop` with all running instances closed. While the user is gaming, use `node scripts/smoke-guides.cjs` for hidden native guide/discovery tests to avoid stealing focus. Native tests use generated fixtures only; full smoke runs pass `--disable-auto-detect`. `npm run package:win` builds a portable x64 directory; `npm run package:mac` builds an arm64 app.

Update the handoff and validation documents when capabilities change. Real TFT validation remains outstanding; synthetic tests do not establish game accuracy. Never reset the first-test budget implicitly, including when switching games; desktop probes and manual recognition share it. Ordinary tests use fake credentials and mock AI fetch; scripts/ai-live.cjs is an explicit paid developer tool outside the desktop budget, never a CI test.
